    全链一图

    电源(电路) ──→ 0xFFFFFFF0(硬编码地址)
   │
   ▼ ①SeaBIOS romlayout.S: reset_vector → entry_post
   │        post.c: 内存检测/POST自检
   │        boot.c: boot_disk() 读磁盘第0扇区, 校验 55AA, 跳到 0x7C00
   ▼ ②GRUB boot.S: _start(0x7C00, 446字节) ──接力──→ diskboot.S ──→ core.img
   │        linux.c: grub_cmd_linux() 读 vmlinuz, 验 "HdrS" 协议
   │        linux.c: grub_linux_boot() EIP=code32_start, 起跳!
   ▼ ③内核 header.S: _start(实模式) → main.c 探测内存
   │        compressed/head_64.S: 切64位, 配5级页表
   │        compressed/misc.c: decompress_kernel() 解压516MB的vmlinux球
   ▼ ④内核真身: head_64.S建页表 → x86_64_start_kernel → init/main.c: start_kernel()
   │        rest_init() → kernel_init() → execve("/sbin/init")
   ▼ ⑤systemd(PID 1): 按依赖图并行拉起服务
   ▼ ⑥getty/login: 登录提示符

    核心思想：每站代码只获得一点点新能力，并用它去找下一站——这叫 bootstrap（自举）。 - CPU 复位后：只会取指执行 → 跳 BIOS - BIOS：会读磁盘扇区（不认识文件系统）→ 读 512 字节 MBR - MBR 446 字节：会算扇区位置 → 拉 GRUB 核心 - GRUB 核心：会读 ext4/FAT 文件系统 → 找到 vmlinuz - 内核：会管理一切 → 拉起 systemd - systemd：会管理服务 → 给你登录界面

    每一跳都"能力升级一点点"，这是开机链条的设计精髓。

    第 0 站：CPU 复位——没有任何代码，只有电路

    按电源 → 电源就绪信号 (PWRGD) → CPU 硬件复位电路动作：

    1. 所有寄存器清零/置默认值
    2. EIP（指令指针）被硬件强制设为 0xFFFFFFF0（4GB 内存地址空间的顶部减 16）
    3. CPU 从这个地址取第一条指令并执行

    关键点：0xFFFFFFF0 不是内存条上的地址，而是被芯片组映射到主板 BIOS 闪存芯片的末尾。 也就是说：CPU 复位后执行的第一条指令，物理上住在 BIOS 芯片里——这就是"固件先于一切"的物理实现。

    这一段没有源码可看——它是 CPU 硅片设计和主板电路设计。 x86 手册（Intel SDM Volume 3, "RESET"章节）描述了这个行为。

    第 1 站：BIOS 固件

    实体主板的 BIOS 是厂商闭源固件。但 SeaBIOS 是一个完整的开源 BIOS 实现—— QEMU 虚拟机里跑的就是它（你之前 qemu-system-x86_64 启动自制 ISO 时，开机头几屏输出就是 SeaBIOS 打的）。 以下代码 100% 等价于实体机 BIOS 干的事。

    1.1 复位向量：0xFFFFFFF0 处的全部内容（2 字节指令）

    文件：seabios-1.17.0/src/romlayout.S 第 688 行

            ORG 0xfff0                    // 【链接器指令】把下面这段放到 BIOS 镜像偏移 0xFFF0 处
                                    // —— 编译后正好落在物理 0xFFFFFFF0，CPU 复位后从这执行
        .global reset_vector
reset_vector:
        ljmpw $SEG_BIOS, $entry_post  // 【一条远跳转】16位实模式远跳：
                                    //   段=BIOS基址, 偏移=entry_post
                                    //   从 4G 顶部跳回 BIOS 主体代码区

    就这一条指令，完成了"从 CPU 复位到 BIOS 开始工作"的交接。 ORG 0xfff0 是整个链条的第一块砖——复位后 CPU 取指的地址和这段代码的链接地址严丝合缝。

    1.2 POST 入口：区分冷启动 / 热启动

    文件：romlayout.S 第 594 行

    entry_post:
        cmpl $0, %cs:HaveRunPost      // 【查询全局标志】之前跑过 POST 吗?
        jnz  entry_resume             // 跑过 → 是 resume(从休眠唤醒/热重启), 走恢复流程
        ENTRY_INTO32 _cfunc32flat_handle_post   // 没跑过 → 冷启动:
                                                //   宏 = 切换到32位保护模式 + 调 C 函数 handle_post()

    ENTRY_INTO32 宏展开后是同文件 26 行处的 transition32（16→32 位切换的经典例程）：

    transition32:
        cli                            // 关中断(切换过程不能被打断)
        cld                            // 清方向标志(字符串操作方向固定)

        // 关 NMI(不可屏蔽中断)——通过写 CMOS 端口
        movl $CMOS_RESET_CODE|NMI_DISABLE_BIT, %eax
        outb %al, $PORT_CMOS_INDEX     // CMOS 端口 0x70: 选寄存器
        inb  $PORT_CMOS_DATA, %al      // 端口 0x71: 读数据(触发 NMI 屏蔽)

        // 打开 A20 地址线——历史包袱:
        // 8086 时代地址回绕到 1MB 的兼容行为, x86 必须显式解锁第 21 根地址线
        inb  $PORT_A20, %al
        orb  $A20_ENABLE_BIT, %al
        outb %al, $PORT_A20

        // 加载中断描述符表 + 全局描述符表, 然后置 CR0.PE 位 → 进入32位保护模式
        lidtw %cs:pmode_IDT_info       // IDT: 中断向量表
        ...                            // lgdt 加载 GDT
        // movl %eax,%cr0 | CR0_PE → PE=1, 此后 CPU 是 32 位状态

    注意：这一段 16 位实模式汇编，是全链条里最"原始"的代码—— 此时的计算机只有：1 个 CPU、1MB 可见内存、没有栈、没有中断、没有设备。 所有现代设施（保护模式、分页、设备驱动）都要从这里一砖一瓦盖起来。

    1.3 POST 自检与设备初始化

    C 代码：seabios-1.17.0/src/post.c 的 handle_post() → maininit()：

    干的事(按序):
  1. 初始化串口/键盘/显示(这时候屏幕开始有输出)
  2. 内存检测(POST 屏幕上跳的内存计数数字)
  3. PCI 总线枚举(扫描所有设备, 给它们分配资源)
  4. 检测硬盘/光驱/USB 存储 → 生成启动设备列表
  5. 建 BIOS 中断表(IVT): 著名的 INT 13h(磁盘服务)/INT 10h(显示服务)
     ——这些"BIOS中断"就是后面 GRUB 446字节代码能调用的"系统调用"

    1.4 读 MBR、校验 55AA、跳 0x7C00 —— BIOS 的最后一击

    文件：seabios-1.17.0/src/boot.c 第 860~920 行（完整原文）

    // 跳转到引导扇区代码前的准备
static void
call_boot_entry(struct segoff_s bootsegip, u8 bootdrv)
{
    dprintf(1, "Booting from %04x:%04x\n", bootsegip.seg, bootsegip.offset);
    struct bregs br;
    memset(&br, 0, sizeof(br));
    br.flags = F_IF;
    br.code = bootsegip;
    // 【传参约定】寄存器 DL=启动盘号(0x80=第一块硬盘)
    //            AX=0xAA55(约定俗成的魔数,引导扇区可用来识别环境)
    br.dl = bootdrv;
    br.ax = 0xaa55;
    farcall16(&br);           // 16位远调用:跳过去, 不再回来
}

// 从磁盘(软盘或硬盘)启动
static void
boot_disk(u8 bootdrv, int checksig)
{
    u16 bootseg = 0x07c0;     // 【历史约定】引导扇区被读到内存 0x7C00 处
                              // (0x07C0:0x0000 的另一种表示, DOS 时代定下)

    // ---- 读第 1 扇区(MBR): 调用 INT 13h ----
    struct bregs br;
    memset(&br, 0, sizeof(br));
    br.flags = F_IF;
    br.dl = bootdrv;          // 驱动器号
    br.es = bootseg;          // 读到哪个内存段
    br.ah = 2;                // INT 13h 功能号 02 = 读扇区
    br.al = 1;                // 读 1 个扇区
    br.cl = 1;                // 从第 1 扇区开始(即 LBA 0, MBR!)
    call16_int(0x13, &br);    // 调 BIOS 磁盘中断服务

    if (br.flags & F_CF) {    // CF 进位标志 = 出错
        printf("Boot failed: could not read the boot disk\n\n");
        return;
    }

    // ---- 校验 MBR 签名 55AA ----
    if (checksig) {
        struct mbr_s *mbr = (void*)0;
        if (GET_FARVAR(bootseg, mbr->signature) != MBR_SIGNATURE) {
            // 屏幕上那句 "Boot failed: not a bootable disk" 就来自这!
            printf("Boot failed: not a bootable disk\n\n");
            return;
        }
    }

    // ---- 跳!控制权交给 MBR 里的代码 ----
    /* 规范化 bootseg:bootip */
    u16 bootip = (bootseg & 0x0fff) << 4;
    bootseg &= 0xf000;
    call_boot_entry(SEGOFF(bootseg, bootip), bootdrv);
}

    BIOS 的一生到此结束（直到下次开机）。它做的最后一件事： 把磁盘第一个扇区（512 字节，含 GRUB 第一段）读进 0x7C00，校验末尾两字节是 55 AA，然后跳过去。

    为什么是 0x7C00？ 1981 年 IBM PC 的设计：DOS 1.0 需要 32KB 内存， 0x7C00 = 32KB - 1024（留 1KB 给引导扇区自己+栈）。这个魔数被 x86 沿用至今。

    为什么验 55AA？ BIOS 固件只有几 KB，不可能理解文件系统/分区表—— 只能约定"最后一个字节是 55 AA 就当它是引导扇区"，把可信度判断降到最低成本。 这就是"约定最小，自由最大"的祖师爷设计。

    第 2 站：GRUB 三段接力

    文件：~/workspace/boot-code-reading/grub-2.14/

    GRUB 的困境：完整功能（菜单、图形、ext4 驱动）需要几百 KB，但 BIOS 只给它 512 字节。 解法 = 三段接力（每段刚够拉起下一段）：

    [MBR 512字节] boot.S ──拉──→ [~30KB] diskboot.S+core.img 前段 ──拉──→ [完整GRUB]

    2.1 第一段：boot.S —— MBR 里的 446 字节

    文件：grub-2.14/grub-core/boot/i386/pc/boot.S 第 119 行起（完整原文+注释）

            /* 告诉汇编器生成 16 位指令——实模式代码! */
        .code16

.globl _start, start;
_start:                           // 【BIOS 把我们加载到 0x7C00 并跳过来】
start:
        /*
         * GRUB 的 MBR 兼容 FAT/HPFS 的 BPB(BIOS参数块)——
         * 某些工具会往引导扇区前部写 BPB, 这里预留位置避开
         */
        jmp  LOCAL(after_BPB)     // 跳过 BPB 兼容区
        nop
        ...                        // (BPB 占位区, 被 grub-install 时按需填充)

LOCAL(after_BPB):

/* ---- 通用初始化 ---- */
        cli                        // 先关中断——栈还没设, 现在被打断就崩

boot_drive_check:
        /*
         * 兼容怪 BIOS:有些 BIOS 不把启动盘号正确放进 DL 寄存器。
         * 这里自检: 如果 GRUB 装在硬盘, 但 DL 不带 0x80 标志(硬盘位),
         * 就强行认定 DL=0x80(第一块硬盘)——因为不可能从别的盘启动
         */
        jmp   3f                   // (grub-setup 可能改写这个跳转)
        testb $0x80, %dl           // DL 的 0x80 位(硬盘标志)设了吗?
        jz 2f
3:      testb $0x70, %dl           // 只接受 0x00-0x0f(软盘)或 0x80-0x8f(硬盘)
        jz 1f
2:      movb $0x80, %dl            // 修正为第一块硬盘
1:
        /*
         * 又一个怪BIOS兼容:有的跳到 07C0:0000 而不是 0000:7C00
         * (两个表示物理地址相同, 但段寄存器值不同, 影响后续寻址)
         * 远跳转强制规范化 CS=0
         */
        ljmp $0, $real_start

real_start:
        /* 设数据段/栈段为 0, 建立干净的段环境 */
        xorw %ax, %ax
        movw %ax, %ds
        movw %ax, %ss
        /* 栈放到 0x2000(引导扇区上方, 不会覆盖自己) */
        movw $GRUB_BOOT_MACHINE_STACK_SEG, %sp
        sti                        // 栈就绪, 安全了, 重开中断

        /* save boot drive (DL) for later use */
        ...                        // (存盘号到变量)

        /* 后续: 用 INT 13h 扩展读(AH=42h, LBA寻址)从 MBR 之后连续读取
           core.img 的前半段(diskboot.S 编译产物), 读到 0x8000 起的内存,
           然后 ljmp 过去 —— MBR 的 446 字节使命完成 */

    这段代码的看点： 1. 大量篇幅在处理"怪 BIOS 兼容"——真实世界 512 字节里一半是踩坑经验 2. 全程只有 INT 13h 一个武器（BIOS 留下的唯一遗产） 3. 编译产物正好 446 字节 + 64 字节分区表 + 55AA = 512

    2.2 第二段：diskboot.S

    文件：grub-2.14/grub-core/boot/i386/pc/diskboot.S

    第二扇区（紧挨 MBR 之后）。任务同样单一： 读 core.img 主体（几十 KB，含 ext2/FAT 文件系统驱动和 GRUB 内核）到内存，跳过去。

    关键点：core.img 各扇区的磁盘位置在 grub-install 安装时硬编码进了 diskboot.S 编译产物—— 这就是为什么"GRUB 安装"必须写盘，而不仅仅复制文件。

    2.3 GRUB 核心复活 → 菜单 → 加载你的内核

    core.img 起来后进入 grub-core/kern/main.c: grub_main()： 初始化 → 加载模块（normal.mod 菜单模块等）→ 读 grub.cfg → 显示菜单 → 等用户选/超时。

    你 ISO 里的 grub.cfg（当时我写的）：

    menuentry "My Kernel 7.3.0 (liang build)" {
    linux /boot/vmlinuz console=tty0 console=ttyS0     ← 这行触发 grub_cmd_linux()
    initrd /boot/initramfs.cpio.gz                      ← 这行触发 grub_cmd_initrd()
}

    2.4 grub_cmd_linux()——GRUB 装载内核的核心函数

    文件：grub-2.14/grub-core/loader/i386/linux.c 第 675 行起（节选原文）

    static grub_err_t
grub_cmd_linux (grub_command_t cmd __attribute__ ((unused)),
                int argc, char *argv[])
{
  grub_file_t file = 0;
  struct linux_kernel_params lh;             // 内核头部的镜像(见下节 header.S)
  ...
  file = grub_file_open (argv[0]);           // 打开 /boot/vmlinuz(你的bzImage!)

  grub_file_read (file, &lh, sizeof (lh));   // 读出内核头部协议字段

  /* ---------- 三重校验: 确认这是 Linux 内核 ---------- */

  // 1. boot_flag 必须是 0xAA55(和 MBR 签名同一个魔数, 双重用途)
  if (lh.boot_flag != grub_cpu_to_le16_compile_time (0xaa55))
    return grub_error (GRUB_ERR_BAD_OS, "invalid magic");

  // 2. header 域必须是 "HdrS"(0x53726448) —— Linux Boot Protocol 的暗号!
  //    且协议版本 >= 0x0203
  if (lh.header != grub_cpu_to_le32_compile_time (GRUB_LINUX_I386_MAGIC_SIGNATURE)
      || grub_le_to_cpu16 (lh.version) < 0x0203)
    return grub_error (GRUB_ERR_BAD_OS, "version too old");

  // 3. loadflags 的 BIG_KERNEL 位必须置位(= 确认是 bzImage 而非古老的 zImage)
  if (! (lh.loadflags & GRUB_LINUX_FLAG_BIG_KERNEL))
    return grub_error (GRUB_ERR_BAD_OS, "must be a bzImage");

  /* ---------- 计算布局 ---------- */
  setup_sects = lh.setup_sects;              // 头部声明: setup 区有几个扇区
  if (! setup_sects)
    setup_sects = GRUB_LINUX_DEFAULT_SETUP_SECTS;
  real_size = setup_sects << GRUB_DISK_SECTOR_BITS;

  /* GRUB 把整个内核安排进内存:
     - setup 区(header.S/main.c 的实模式部分) → 实模式地址 0x90000 一带
     - 内核主体(压缩球)      → code32_start 指定的 0x100000(1MB, 低端 RAM 安全区)
     - 命令行/console=ttyS0  → 按 boot protocol 塞进 params 页
     - initramfs             → 高内存区, 地址写进 params 的 ramdisk_image 字段
  */
  ...
  /* 然后 grub_cmd_initrd() 加载你的 initramfs.cpio.gz 到高内存,
     把地址/长度写进 lh.ramdisk_image / lh.ramdisk_size */
}

/* ---------- 最后起跳: grub_linux_boot() ---------- */
static grub_err_t
grub_linux_boot (void)
{
  ...
  /* 切回实模式模拟内核期望的环境, 把实模式参数块指针放进 ESI,
     然后把 EIP 设为内核头声明的入口地址 */
  state.ebp = state.edi = state.ebx = 0;
  state.esi = ctx.real_mode_target;          // ESI = 参数块物理地址(内核靠它找到一切)
  state.esp = ctx.real_mode_target;
  state.eip = ctx.params->hdr.code32_start;  // EIP = 0x100000(内核32位入口)
  return grub_relocator32_boot (relocator, state, 0);   // ★ GRUB 使命终结, 控制权交内核
}

    GRUB 一生的总结：从 BIOS 手里接过 512 字节的惨淡开局， 一路攒家底（文件系统驱动、内存布局、菜单），最后把 vmlinuz 摆进内存、 参数放好、EIP 指过去——干净离场。

    第 3 站：Linux 内核自解压（bzImage 内部三段结构）

    回忆 bzImage 的结构（你编译产物 17MB）：

    bzImage (17MB)
├── 实模式 setup 区    ← header.S + main.c(arch/x86/boot/)      【GRUB 跳到这】
├── 解压器             ← compressed/head_64.S + misc.c            【第二跳到这】
└── 压缩的 vmlinux 球  ← 你那个 516MB 内核, xz/gz 压缩成 ~10MB   【第三跳到这】

    3.1 header.S —— GRUB 跳进来的落点，也是"协议"本身

        /*
         * 解压目标区域和压缩球当前位置可能重叠。
         * 解法: 先把压缩球整体搬到解压缓冲区的【尾部】,
         * 这样解压时从头往后展开, 不会踩到还没解压的数据
         */
        leaq (_bss-8)(%rip), %rsi        // 源: 压缩球当前位置
        leaq rva(_bss-8)(%rbx), %rdi     // 目的: 缓冲区末尾
        movl $(_bss - startup_32), %ecx
        shrl $3, %ecx                    // 按字节算→按8字节(quad)算
        std                               // 反方向拷贝!(从尾部往前搬)
        rep movsq                         // CPU 块拷贝指令, 一条指令搬完
        cld                               // 恢复正方向

        /* GDT 可能被刚才的拷贝覆盖了, 重新加载一份新的 */
        leaq rva(gdt64)(%rbx), %rax
        leaq rva(gdt)(%rbx), %rdx
        movq %rdx, 2(%rax)
        lgdt (%rax)                       // 重新装全局描述符表

    3.3 misc.c —— decompress_kernel()，vmlinux 复活的地方

    文件：arch/x86/boot/compressed/misc.c 第 345 行（原文）

    extern unsigned char input_data[];        // ← 压缩的 vmlinux 球!
                                          //   编译时作为一个"数据数组"嵌进解压器——
                                          //   你那 516MB 的 vmlinux, 压缩后 ~10MB,
                                          //   以字节数组的形式躺在 bzImage 里
extern unsigned int input_len, output_len;

unsigned long decompress_kernel(unsigned char *outbuf, unsigned long virt_addr,
                                void (*error)(char *x))
{
        unsigned long entry;

        /* 解压器自己也要内存(它跑在内核起来之前): 用静态预留的 boot_heap */
        if (!free_mem_ptr) {
                free_mem_ptr     = (unsigned long)boot_heap;
                free_mem_end_ptr = (unsigned long)boot_heap + sizeof(boot_heap);
        }

        /* ★ 真正的解压: input_data(xz/gz压缩的vmlinux) → outbuf
           屏幕上那句 "Decompressing Linux... Parsing ELF... done" 期间执行的就是这 */
        if (__decompress(input_data, input_len, NULL, NULL, outbuf, output_len,
                         NULL, error) < 0)
                return ULONG_MAX;        // 解压失败→error()打日志→死机

        entry = parse_elf(outbuf);        // 解出来的是完整ELF文件!
                                          // 解析ELF头,把各段(Program Section)摆到
                                          // 虚拟地址, 拿到入口地址(vmlinux的_entry)
        handle_relocations(outbuf, output_len, virt_addr);
                                          // KASLR 重定位: 把内核随机挪到
                                          // 一个安全偏移(防内存攻击), 修正所有地址引用

        return entry;                     // 入口地址交还给 head_64.S, 它 ljmp 过去
}
